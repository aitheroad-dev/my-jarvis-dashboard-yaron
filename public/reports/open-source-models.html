Running open models locally — the full landscape

What "open" actually means, who makes these models and why, how good they are versus Claude/GPT, how you run them on a Mac, and exactly what to run on your hardware.

Compiled 25 June 2026 · researched live across 5 parallel streams (families, licenses, runtimes, benchmarks, ecosystem) · every non-obvious claim links a source · fast-moving facts flagged MED/LOW confidence.

TL;DR — the five things that matter
  1. "Open weight" ≠ "open source." Almost every famous "open" model (Llama, Qwen, Gemma) ships weights only — the training data and recipe stay closed. Truly-open (data + code + checkpoints) is rare: OLMo, SmolLM, Pythia.
  2. The gap to the closed frontier is ~3 months. The best open models now trail Claude/GPT/Gemini by roughly a quarter and a few index points — the narrowest ever. On math and tool-use the gap has effectively closed.
  3. China leads open releases now. Qwen, DeepSeek, Kimi, GLM drove Chinese open-model usage from ~1% to ~30% in about a year. Meta carries the US open flag (with caveats); OpenAI/Anthropic stay closed.
  4. On a Mac, MLX won. Apple's MLX engine is now the fastest path on Apple Silicon — Ollama itself switched its Mac engine to MLX in March 2026. "GGUF is what you run on a Mac" is outdated.
  5. Your 48 GB M4 Pro is a strong local box. It runs anything ≤32B comfortably and 70B-class in a tight quant. The right move is hybrid: local for privacy/volume/routine, cloud for frontier reasoning. Jump to recommendations →

1Open source vs open weight — the distinction everything hinges on

This is the single most misunderstood thing in the field, and it has real legal and scientific consequences. Most "open source AI" talk is, strictly, wrong.

The OSI definition (OSAID 1.0)

The Open Source Initiative — keepers of the term for ~25 years — released the Open Source AI Definition on 28 Oct 2024. To be "open source," an AI system must grant four freedoms (Use, Study, Modify, Share), which requires three things in their preferred form:

  • Data information — enough detail about the training data that a skilled person could build a substantially equivalent system. (Notably, OSAID does not require shipping the full dataset — the most-contested compromise.)
  • Code — the full training + inference pipeline.
  • Parameters — the weights (and ideally intermediate checkpoints).

By this bar, almost no famous "open" model qualifies — they fail on missing data/recipe, restricted licenses, or both.

Why it matters to you
For using / fine-tuning / deploying, an open-weight model with an Apache/MIT license is all you need — and there are plenty. For reproducibility, auditability, or true data provenance, only the fully-open families deliver. And always read the license: "open weight" is not "do anything" — Llama's terms in particular bind you (see §3).

2The major model families

These are the families people actually run in mid-2026. Sizes, what each is best at, the one to run locally, and the license. (⚠️ = a mid-2026 release confirmed to exist but with specs from secondary sources — verify the exact model card before betting production on it.)

META

Llama 4 — Scout & Maverick

First natively-multimodal MoE Llama (Apr 2025). Scout 109B/17B-active (10M context, single-GPU); Maverick 400B/17B-active. Behemoth (~2T) still unreleased. Many still run dense Llama 3.3 70B / 3.1 8B locally.

Best at: general + long-context multimodal. License: Llama Community — >700M MAU needs Meta's permission; EU barred from the multimodal models; "Built with Llama" attribution.

ALIBABA

Qwen3 / Qwen3.5 ⚠️

The most versatile open family. Dense 0.6–32B + MoE 30B-A3B / 235B-A22B. Qwen3-Coder is a top open coder; Qwen-VL for vision; 119 languages.

Best at: the Apache-licensed default for general/coding/multilingual. Run: Qwen3-32B or 30B-A3B. License: Apache-2.0 (a few VL variants excepted).

GOOGLE

Gemma 3 / Gemma 4 ⚠️

Best quality-per-parameter in small/mid sizes. Gemma 3: 270M–27B, text+image, 128K ctx; Gemma 3n targets phones. Gemma 4 (2026) reportedly moved to Apache-2.0.

Best at: small multimodal, on-device. Run: Gemma 3 27B. License: Gemma Terms (custom, 1–3) → Apache-2.0 (4 ⚠️).

DEEPSEEK

DeepSeek V3 / R1 / V4 ⚠️

671B MoE / 37B-active. R1 (Jan 2025) redefined open reasoning via RL; distilled into 1.5–70B dense models anyone can run. V3.2 adds sparse-attention efficiency.

Best at: reasoning, also strong general/coding. Run: R1-Distill-Qwen-32B (full V3/R1 needs ~8×H100). License: MIT.

MISTRAL (FR)

Mistral — fragmented licensing

Apache for small/edge (Mistral 7B, Mixtral, Small 3.1/4, Ministral 3, Magistral=reasoning, Devstral=agentic coding, Pixtral=vision). The large ones (Large 2, Codestral) are research/commercial-only.

Run: Mistral Small 3.1/4 (24B) or Devstral. License: Apache-2.0 (small) / MRL non-commercial (large).

MICROSOFT

Phi-4

Small models that punch up via curated "textbook-quality" synthetic data. Phi-4 14B (reasoning/math), Phi-4-mini 3.8B, Phi-4-multimodal. Weaker on world-knowledge/multilingual.

Best at: reasoning-per-parameter, runs on 12 GB. License: MIT — the cleanest of all.

OPENAI

gpt-oss-20b / 120b

OpenAI's first open weights since GPT-2 (Aug 2025). MoE reasoning models: 20b (3.6B active, runs on 16 GB) ≈ o3-mini; 120b (5.1B active, single 80 GB GPU) ≈ o4-mini. Native tool-use, adjustable reasoning effort. Text-only.

Best at: reasoning + agentic tool-use. License: Apache-2.0.

NOTABLE OTHERS

GLM · Kimi · Nemotron · Cohere · Yi

GLM (Zhipu, MIT) & Kimi K2 (Moonshot, 1T-MoE, modified-MIT) — top open coders/agents. Nemotron (NVIDIA, custom license). Command-A (Cohere, historically non-commercial). Yi (01.AI, Apache).

Why benchmark numbers mislead (read before trusting any score)
  • Contamination — public benchmark questions leak into training data; some 2026 models drew scrutiny for "statistically unusual" scores.
  • Saturation — MMLU, HumanEval, AIME now cluster near 100% and no longer separate models. Only GPQA-Diamond, SWE-bench Verified, LiveCodeBench, "Humanity's Last Exam" still discriminate.
  • Arena gaming — the "Leaderboard Illusion" paper showed labs test dozens of private variants and publish only the best; Arena rewards longer, confident answers regardless of substance.
  • Noise — top models sit within overlapping ±15–20 Elo confidence intervals; exact ordering at the top is often meaningless.
Many flashy 2026 model names in the sources ("DeepSeek V4 Pro," "GLM-5.2," etc.) are real-ish but hard to pin to one primary card — treat exact scores as ±a few points.

Eight tools matter. On a Mac the practical choice is Ollama (developers, one command) or LM Studio (GUI). Both now run Apple's MLX engine and expose the same OpenAI-compatible API.

The big 2026 shift — MLX won on Apple Silicon
Apple's MLX framework (built natively on Metal + unified memory) is now faster for token generation — so much so that Ollama switched its Mac inference path from llama.cpp to MLX in March 2026. GGUF/llama.cpp still wins on portability, very long context, and prefill on pre-M5 chips, but the lead has flipped. Bottom line: on a modern Mac, prefer the MLX path (Ollama >32 GB, or LM Studio's MLX engine).

The universal trick — every tool speaks OpenAI

Point any OpenAI SDK at the local server. Two overrides and your existing code works unchanged — so you can prototype in a GUI and graduate to code without rewriting:

# OpenAI-compatible, fully local
client = OpenAI(
  base_url="http://localhost:11434/v1",  # Ollama (LM Studio :1234, llama.cpp/MLX :8080)
  api_key="local",                          # any non-empty string; ignored
)

6Quantization & hardware sizing

Quantization is what lets big models fit on normal hardware — it shrinks each weight from 16 bits to ~4, trading a little quality for ~4× less memory.

  • GGUF quants (llama.cpp/Ollama): Q4_K_M is the standard sweet spot; Q5_K_M/Q6_K for more quality, Q8_0 near-lossless. Below Q4 quality drops fast.
  • MLX quants (Apple): 4-bit/8-bit, ~8–10% smaller files than GGUF; new DWQ learned-quantization lets a 4-bit model approach 6/8-bit quality.
  • The RAM rule: at 4-bit, a model needs ≈ 0.6 GB per billion params + ~25–30% overhead for context. And macOS only hands ~75% of unified RAM to the GPU by default (raise via sysctl iogpu.wired_limit_mb; resets on reboot). Leave ~4–8 GB for the OS.

Live trends shaping what you'll run

  • MoE is the default — huge total params, tiny active fraction (~3–6%) per token. Decouples knowledge breadth from inference cost (Qwen3 235B-A22B, DeepSeek 671B/37B, Kimi K2 1T/32B).
  • Reasoning / test-time compute — "thinking" models that spend inference compute to reason (post-DeepSeek-R1).
  • Small-but-capable + on-device — a parallel track to the giant MoEs; Gemma/Phi/SmolLM run on phones & laptops.
  • Agentic / tool-use native — multi-step planning & tool calling trained in, not bolted on.
  • Long context — 1M-token windows reaching open weights; multimodal by default.
  • New architectures — Mamba/SSM and Transformer-hybrids (Granite 4, Falcon-H1) for cheaper long-context — emerging, not yet dominant.

8Local vs cloud — the decision framework

The honest gap: open weights rival closed on many tasks, but for multi-step reasoning, large multi-file code, and dense synthesis, frontier models (Claude/GPT) remain consistently more reliable. So route by task.

Choose LOCAL when…

  • Data can't leave your machine — privacy/compliance/secrets. This alone decides it.
  • High, predictable volume — break-even ≈ 500K tok/day (7B) or ~2M tok/day (70B). Over ~5M/day local wins outright.
  • Fine-tuning a small model on your data for a narrow, repeated task (can beat a generic API).
  • Offline / zero-dependency operation, or routine work (classification, extraction, summarization, RAG).

Choose CLOUD (Claude/GPT) when…

  • Frontier reasoning — complex multi-file code, dense legal/technical synthesis, subtle multi-step planning.
  • Low / spiky volume — a few hundred-K tokens/day; cloud is cheaper and zero-ops.
  • You want always-latest capability and no infra burden.
  • You lack the RAM for the model tier the task needs.
The default-correct answer for a solo builder: hybrid
Privacy-sensitive & high-volume baseline → local; frontier-reasoning & spiky overflow → cloud. Because both expose the OpenAI API, the routing layer is a thin shim, not a rewrite.

Recommended path for PAI
  1. Install Ollama (brew install ollama) — on your 48 GB Mac it uses the fast MLX path automatically, and exposes localhost:11434/v1.
  2. Pull a starter set: qwen2.5-coder:32b (coding) + llama3.2:3b (fast) + gpt-oss:20b (reasoning/tools).
